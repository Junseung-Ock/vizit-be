# document-issue

이슈 작업이 완료됐을 때 호출한다. git 로그와 변경 파일을 분석해 작업 문서를 생성하고 `.claude/work-logs/`에 저장한다.

## 실행 절차

1. 현재 브랜치명에서 이슈 번호와 제목을 추출한다.
   ```bash
   git symbolic-ref --short HEAD
   # 예) feature/13-kakao-oauth → 이슈번호: 13, 제목: kakao-oauth
   ```

2. develop 대비 커밋 로그와 변경 파일 목록을 조회한다.
   ```bash
   git log develop..HEAD --oneline
   git diff develop..HEAD --name-only
   ```

3. 변경된 핵심 파일들을 읽어 작업 내용을 파악한다.

4. 아래 형식으로 `.claude/work-logs/{이슈번호}-{제목}.md` 파일을 생성한다.

---

## 문서 형식

```markdown
# #{이슈번호} {제목}

- **브랜치**: feature/{이슈번호}-{제목}
- **작업일**: {날짜}

## 작업 내용
> 무엇을 왜 만들었는지 2~3줄 요약

## 변경된 파일
- `경로/파일명` — 변경 이유

## 주요 결정 사항
> 설계 선택, 트레이드오프, 주의해야 할 동작 등

## 다음 작업 시 참고할 점
> 이 작업과 연관된 후속 작업이나 의존 관계
```

---

## CLAUDE.md 업데이트 검토

work-log 문서 생성 후, 아래 항목이 변경됐는지 확인하고 해당되면 CLAUDE.md를 업데이트한다.

| 확인 항목 | 업데이트 대상 |
|-----------|-------------|
| 새 도메인 클래스 추가 (`domain/` 하위) | `## 주요 도메인` |
| `build.gradle`에 새 의존성 추가 | `## 기술 스택` |
| 새 패키지 추가 (`infra/`, `global/` 등) | `## 패키지 구조` |

변경이 없으면 CLAUDE.md는 수정하지 않는다.

## 완료 후

아래를 안내한다:
- 생성된 work-log 파일 경로
- CLAUDE.md 업데이트 여부
- PR 올리기 전 두 파일 모두 커밋에 포함할 것
